# Open Logic edition tools

Local source-registry, synchronization, edition-metadata and pinned-source tools. Install from this checkout with `python -m pip install -e .` using Python 3.11 or later. The data and schema files remain in this checkout.

`olpkit units registry --check` verifies the shared path-to-unit map. `olpkit sync plan --from COMMIT --to COMMIT --out DIRECTORY` makes source-change packets. `olpkit sync plan --check DIRECTORY` replays their exact Git identities. `olpkit lint structure --en SOURCE --tr TARGET` compares explicit TeX structure; it does not certify mathematical or linguistic equivalence.

`olpkit edition import-manifest --repo REPOSITORY --adapter jv --out STAGING` converts an existing manifest into `olp-edition.toml` and `units.jsonl`. Other supplied adapters are `gu`, `bn` and `mr`. It checks actual English files against the pinned Git blobs and inherited source hashes, and reads every target file. Existing differing metadata is not overwritten. An owner can omit `--out` to create the two new files in that owner's repository.

`olpkit edition validate --repo REPOSITORY --metadata-dir STAGING` checks staged metadata against the repository. Omit `--metadata-dir` after the owner adds the files to the repository. Unknown keys, duplicate identities, missing units, incorrect pins and changed source/target bytes fail validation.

In this ledger, **current** means that the recorded source blob matches the edition pin. It is not a canon-use, translation-quality, completeness-of-proof or human-review certificate. `by.method = "inherited"` with null model/effort/date records a historical attribution gap; it does not credit the converter with translation work. Preserve established edition-level model attribution and consult the original production records before assigning per-unit models. A model and its effort must be recorded together. No fabricated dates or retrospective claims of earlier canon consultation are permitted.

`olpkit fetch --repo REPOSITORY` reads the edition's full source pins and fills the shared cache. `--metadata-dir STAGING` uses staged contracts. Each export contains exact Git blob bytes, including licences and files marked export-ignore. Checkout line-ending filters do not affect it. A warm fetch verifies the existing export without downloading again. A mismatched export is reported, not silently replaced. `OLPKIT_CACHE` can select another cache directory.

The Python assembly interface `SourceCache.require` is read-only and never fetches implicitly. Build patches in `data/shims` identify the precise before/after text, language/script/engine conditions, reason and pinned pilot evidence. `apply_shims` returns changed copies and records every match; missing or repeated matches fail. It does not rewrite translation units or alter the cache. These inherited patches preserve build behavior; they do not establish rendered quality by themselves.

`olpkit drivers --repo REPOSITORY --out OUTPUT` generates the pinned textbook drivers and three preamble files. Staged contracts can be supplied with `--metadata-dir`. The default book is `sets-logic-computation`; `--book` selects book data. `--check` compares the generated bytes with the existing outputs. A changed upstream driver requires explicit review of its transformations and reader labels. Current Javanese and Gujarati settings come from their pinned pilots. Translated labels and font settings remain in language data, outside Python modules and drivers. Font overrides require recorded reasons.

`olpkit assemble --repo REPOSITORY --ref BOOK_COMMIT --edition-ref EDITION_COMMIT --product slc-screen-pdf --out OUTPUT` assembles the pinned English source, canonical translations, book inputs, generated drivers, fonts and component notices. Use separate immutable references while a textbook branch and the default branch carry different input layouts. Omit `--edition-ref` when both live at the same commit. `--metadata-dir` accepts an explicit staged contract; source and target bytes are still checked at the immutable edition commit. The command reads local Git objects and verified cache exports without network access or TeX execution. Outputs must be under the builder's named output directory; differing existing outputs are preserved.

`ASSEMBLY.json` records every input origin and assembled file hash. Repeating assembly gives identical bytes; `--check` compares the entire existing tree. An explicitly new unit with no target is filled with the pinned English text without a translation marker. A missing or changed file declared translated is an error. Stale units remain identified as stale. The assembler inserts locale flags without changing wording. Legacy textbook prose patches are not executed: their identities remain in the report until the source owner reconciles them into canonical units, token settings or build shims.

`olpkit build --repo REPOSITORY --ref COMMIT --product slc-screen-pdf --out OUTPUT` compiles the assembled book under the shared TeX mutex and a capped Windows process tree. It records commands, input hashes, imports, convergence and overfull boxes. An occupied slot starts no engine. Unimplemented acceptance gates are explicitly recorded; a compiled PDF alone is not release acceptance.

Install the PDF inspection dependencies with `python -m pip install -e ".[pdf]"`. `olpkit pdf compare --first FIRST.pdf --second SECOND.pdf --out OUTPUT` compares page counts and exact UTF-8 `pdftotext` bytes, retaining the extractions and a difference preview. It does not normalize away words, whitespace or formulas. Equality is not called reproducibility unless `--first-build` and `--second-build` bind two distinct completed builds, their unchanged source inputs, engine version and actual PDF bytes.

`olpkit pdf links --first READER.pdf --out OUTPUT` measures painted link text and its annotation rectangles. It checks one link colour, at least 7:1 contrast on white paper, and citation destinations split by unlinked text on the same line. Reports retain page numbers, rectangles, text and measured colours for inspection. Distinct mentions of the same bibliography entry can need contextual adjudication. Rotated/cropped pages, unsupported colour spaces, image-backed links and links without extractable text remain explicitly unmeasured; they do not pass silently. Link destination validity, tables, font scale and semantic fidelity require their own checks.

Language profiles declare the link colour and contrast threshold. The common preamble retains natbib separators inside each citation's existing link, preserving separate destinations for different citation keys. Output must still be checked with the PDF link command and visually inspected.

Driver generation checks the mapped driver labels; assembly verifies bytes and structure of the input set. Neither certifies book translation. Existing source files, publication history and substantive corrections must remain intact.
