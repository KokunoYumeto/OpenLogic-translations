# Open Logic edition tools

Local source-registry, synchronization, edition-metadata and pinned-source tools. Install from this checkout with `python -m pip install -e .` using Python 3.11 or later. The data and schema files remain in this checkout.

The glossary adapter preserves authored names, definitions, symbols and explicit plurals. It takes its order from the native book's emitted glossary and requires complete source-to-witness coverage. Glossary references retain their actual labels; sentence casing requires an evidenced language rule. HTML binding checks every entry and link before placing each destination on its term. This adapter does not translate definitions or establish full-reader acceptance.

The bibliography adapter retains the native `.bbl` entries and derives author–date citation labels from the corresponding `.aux`, using evidenced natbib punctuation. Each citation occurrence remains linked to its exact entries, including citations in footnotes. Native diagram descriptions use the language owner's source-bound text, with concise image labels, visible links to the full descriptions and links back to each diagram. These components retain their source evidence separately from reader-facing text.

`olpkit units registry --check` verifies the shared path-to-unit map. `olpkit sync plan --from COMMIT --to COMMIT --out DIRECTORY` makes source-change packets. `olpkit sync plan --check DIRECTORY` replays their exact Git identities. `olpkit lint structure --en SOURCE --tr TARGET` compares explicit TeX structure; it does not certify mathematical or linguistic equivalence.

`olpkit edition import-manifest --repo REPOSITORY --adapter jv --out STAGING` converts an existing manifest into `olp-edition.toml` and `units.jsonl`. Other supplied adapters are `gu`, `bn` and `mr`. It checks actual English files against the pinned Git blobs and inherited source hashes, and reads every target file. Existing differing metadata is not overwritten. An owner can omit `--out` to create the two new files in that owner's repository.

`olpkit edition validate --repo REPOSITORY --metadata-dir STAGING` checks staged metadata against the repository. Omit `--metadata-dir` after the owner adds the files to the repository. Unknown keys, duplicate identities, missing units, incorrect pins and changed source/target bytes fail validation.

In this ledger, **current** means that the recorded source blob matches the edition pin. It is not a canon-use, translation-quality, completeness-of-proof or human-review certificate. `by.method = "inherited"` with null model/effort/date records a historical attribution gap; it does not credit the converter with translation work. Preserve established edition-level model attribution and consult the original production records before assigning per-unit models. A model and its effort must be recorded together. No fabricated dates or retrospective claims of earlier canon consultation are permitted.

`olpkit fetch --repo REPOSITORY` reads the edition's full source pins and fills the shared cache. `--metadata-dir STAGING` uses staged contracts. Each export contains exact Git blob bytes, including licences and files marked export-ignore. Checkout line-ending filters do not affect it. A warm fetch verifies the existing export without downloading again. A mismatched export is reported, not silently replaced. `OLPKIT_CACHE` can select another cache directory.

English textbook references use `olpkit build --english --olp-pin FULL_COMMIT --product PRODUCT --out OUTPUT`. Registered products include `slc-screen-pdf` (Sets, Logic, Computation) and `il-screen-pdf` (Intermediate Logic). Each product selects its own registered book pin, native driver and source mounts. Its import lock is written only after a successful English recorder build and is bound to all four source pins and the actual PDF. Identical unit lists do not make a witness for one book valid for another. Original authors and component notices remain in the pinned sources.

Language-specific book assembly profiles may live in `data/assembly/LOCALE/PRODUCT.json`; existing single-product profiles in `data/assembly/LOCALE.json` remain supported. A different book needs its actual localized book units, driver policy and choice ledger before a translated build is available. Reusing byte-identical English book units still requires the corresponding accepted target text, canon-use evidence and a check of the new book context. Registering an English source is not completion of a translated textbook.

New book profiles can bind their native `book.toml` instead of a legacy pilot manifest. Pass `--book-ledger CHOICE_LEDGER.jsonl` to `assemble` or `build`; every registered book unit must match its pinned source, committed target, producer attribution and actual private review record. The final assembled tree must retain every target byte. The private choices remain outside the assembled sources; hashes and coverage do not constitute linguistic acceptance. A book's driver policy may select its own preamble templates while retaining the common language fonts and settings.

The Python assembly interface `SourceCache.require` is read-only and never fetches implicitly. Build patches in `data/shims` identify the precise before/after text, language/script/engine conditions, reason and pinned pilot evidence. `apply_shims` returns changed copies and records every match; missing or repeated matches fail. It does not rewrite translation units or alter the cache. These inherited patches preserve build behavior; they do not establish rendered quality by themselves.

`olpkit drivers --repo REPOSITORY --out OUTPUT` generates the pinned textbook drivers and three preamble files. Staged contracts can be supplied with `--metadata-dir`. The default book is `sets-logic-computation`; `--book` selects book data. `--check` compares the generated bytes with the existing outputs. A changed upstream driver requires explicit review of its transformations and reader labels. Current Javanese and Gujarati settings come from their pinned pilots. Translated labels and font settings remain in language data, outside Python modules and drivers. Font overrides require recorded reasons.

`olpkit assemble --repo REPOSITORY --ref BOOK_COMMIT --edition-ref EDITION_COMMIT --product slc-screen-pdf --out OUTPUT` assembles the pinned English source, canonical translations, book inputs, generated drivers, fonts and component notices. Use separate immutable references while a textbook branch and the default branch carry different input layouts. Omit `--edition-ref` when both live at the same commit. `--metadata-dir` accepts an explicit staged contract; source and target bytes are still checked at the immutable edition commit. The command reads local Git objects and verified cache exports without network access or TeX execution. Outputs must be under the builder's named output directory; differing existing outputs are preserved.

`ASSEMBLY.json` records every input origin and assembled file hash. Repeating assembly gives identical bytes; `--check` compares the entire existing tree. An explicitly new unit with no target is filled with the pinned English text without a translation marker. A missing or changed file declared translated is an error. Stale units remain identified as stale. The assembler inserts locale flags without changing wording. Legacy textbook prose patches are not executed: their identities remain in the report until the source owner reconciles them into canonical units, token settings or build shims.

`olpkit build --repo REPOSITORY --ref COMMIT --product slc-screen-pdf --out OUTPUT` compiles the assembled book under the shared TeX mutex and a capped Windows process tree. It records commands, input hashes, imports, convergence and overfull boxes. An occupied slot starts no engine. Unimplemented acceptance gates are explicitly recorded; a compiled PDF alone is not release acceptance.

Install the PDF inspection dependencies with `python -m pip install -e ".[pdf]"`. `olpkit pdf compare --first FIRST.pdf --second SECOND.pdf --out OUTPUT` compares page counts and exact UTF-8 `pdftotext` bytes, retaining the extractions and a difference preview. It does not normalize away words, whitespace or formulas. Equality is not called reproducibility unless `--first-build` and `--second-build` bind two distinct completed builds, their unchanged source inputs, engine version and actual PDF bytes.

`olpkit pdf links --first READER.pdf --out OUTPUT` measures painted link text and its annotation rectangles. It checks one link colour, at least 7:1 contrast on white paper, and citation destinations split by unlinked text on the same line. Reports retain page numbers, rectangles, text and measured colours for inspection. Distinct mentions of the same bibliography entry can need contextual adjudication. Rotated/cropped pages, unsupported colour spaces, and image-backed links remain explicitly unmeasured. XeLaTeX builds can also measure opaque rectangular fills and the identified Open Logic vector logo when PDF paint order and rendered colours corroborate the measurement. Other links without extractable text stay unmeasured. Link destination validity, tables, font scale and semantic fidelity require their own checks.

`olpkit pdf glyphs --first READER.pdf --out OUTPUT` checks the actual PDF glyph trace as well as Poppler extraction. It catches unmapped glyphs that a word extractor can silently guess as ordinary characters, preserves complete occurrence and page counts, and records bounded coordinate examples. Valid `ActualText` replacements are matched to individual glyph occurrences, including Indic shaping; they cannot excuse a painted `.notdef` glyph. Unsupported replacement sequences and private-use mappings remain unresolved; an ordinary square is not automatically a missing glyph or proof-end mark. The shared build records this encoding gate after compilation without claiming visual or mathematical fidelity from it.

Language profiles declare the link colour and contrast threshold. The common link preamble applies that colour after the OLP class's begin-document setup, and retains natbib separators inside each citation's existing link, preserving separate destinations for different citation keys. Build inspection also detects a different painted colour, even when it passes contrast. For XeLaTeX it accepts the exact three-decimal serialization of the declared colour as well. Output must still be visually inspected.

Driver generation checks the mapped driver labels; assembly verifies bytes and structure of the input set. Neither certifies book translation. Existing source files, publication history and substantive corrections must remain intact.

If a prepared build stopped because the TeX slot was occupied and started no engine, the same `build` command with `--resume` reuses its output directory. Assembly generation checks every existing byte against the requested source revision and current profiles before reuse. The prior receipt is preserved under `attempts/`; a per-directory lock prevents concurrent invocations. Started, failed, completed or changed-input builds cannot use this route. Resume only at a later substantive checkpoint, never by polling the slot. This avoids another full staging copy for each occupied-slot attempt.

`olpkit check credits --source ASSEMBLED_TREE --policy POLICY.json --out OUTPUT` checks the actual component notices against separately specified witness hashes. Policies account for original text, textbook, translation, portraits, photographs, fonts and bundled packages. Missing or altered notices fail. Unresolved requirements remain incomplete. Add `--pdf READER.pdf --build BUILD.json` to check actual reader attribution and bind it to the unchanged source assembly; source notices alone do not establish reader attribution. The report is a notice-preservation check, not copyright clearance or a review of translation quality.

Builder code produced by OpenAI Codex — GPT-6 Astra, Ultra effort. This is a code attribution, not attribution of the inherited translations or original Open Logic Project texts.

`olpkit figures --source ASSEMBLED_TREE --context EXPANDED_TEX --profile PROFILE.json --out OUTPUT` renders complete native TikZ pictures or tableaux using the book's own preamble. The language-neutral profile binds the exact assembly, expanded source, configuration witnesses, engine and source date. Tableaux retain their formulas, branches, numbered lines, rule references and closure marks through the native renderer. One capped process holds the shared TeX slot. `--resume` applies only to a verified prior occupied-slot attempt that started no engine; use it at a later substantive checkpoint. Exported vectors still require source comparison, visual review and localized descriptions before web-reader acceptance.

The optional `epub` dependencies support `olpkit.epubpackage.package_html`: a pure packaging function for already-converted HTML. It takes edition metadata, an ordered unit list, exact image/font bytes and localized notice documents. It produces a deterministic EPUB and preservation measurements without staging copies. Language, reading direction, labels, CSS and notices come from the supplied data. The function rejects missing units, unresolved links, absent source annotations and changed mathematical structure. It is not yet a source-to-HTML converter or the `export epub` command; source binding, PDF numbering, credits, visual checks and EPUBCheck remain required before release.
